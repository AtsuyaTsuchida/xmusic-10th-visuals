# video — 曲につける映像の素材づくり

`../../x-music-videos/` の作品映像 21 本から、字幕や文字が映っているカットを除いた素材を作る。
元の動画は読むだけで、結果は `../../x-music-videos/notext/` に別ファイルとして書き出す(音声なし、H.264)。

## 消す基準

- **消す**: タイトル、クレジット、字幕、説明文、画面いっぱいの UI、スクリーンに映した大きな文字や時刻表示。
- **残す(写り込み)**: 機材のロゴ、服の文字、遠くの看板、合板の刻印、物体検出の小さなラベルなど、画面のごく一部の小さな文字。
  `analyze.py` の `BIG`(文字の面積が画面の 1.2% 以上かどうか)で分け、目で見て例外を `work/overrides.json` に書いた。
- 20 秒以下のカットは、文字が一部でも映ればカットごと消す。それより長いカットは、文字が映っている時間帯(前後 0.75 秒の余白つき)だけを消す。
- 黒味(真っ暗)が 0.75 秒以上続くところも消す。

## 手順

```bash
cd tools
swiftc -O textscan.swift -o textscan                      # 文字検出(macOS の Vision)
./scan_all.sh ../../../x-music-videos                     # 文字と、1コマごとの画面変化量・明るさを work/ に書く(15分ほど)
python3 analyze.py ../../../x-music-videos                # カットの切れ目と消す時間帯 → work/plan/<ID>.json
python3 sheet.py runs ID ../work/sheets/ID.runs.jpg       # 検出した文字の一覧画像(確認用)
python3 sheet.py keep ID ../work/sheets/ID.keep.jpg       # 残す部分の一覧画像(確認用)
python3 export.py ../../../x-music-videos/notext          # 書き出し。segments.csv に元動画との対応
python3 verify.py ../../../x-music-videos/notext          # 書き出した動画をもう一度文字検出にかける
```

## 注意

- 文字検出は縦書きの日本語と、装飾の強い大きな数字を見逃す(改造イントナルモーリの縦書きタイトル、小田急の時計表示)。
  見逃しは `sheet.py keep` の一覧を目で見て `work/overrides.json` に足す。
- カットの切れ目はハードカットだけを拾う。ディゾルブは拾えないので、その場合は長いカット扱いになる。
- `Dialect x Music` は全編が文字入りなので、書き出しファイルがない。

## 波形だけの映像

`tools/wave.sh 音源.wav 出力.mp4 [開始秒 長さ秒]` で、音に合わせて動く横一本の波形(黒地に白線)を作る。
1920x540 (32:9)、30fps。1コマに、その瞬間から 1/30 秒ぶんの音を左から右へ描く(左右の音は足して1本)。
線の太さ・波の高さ・コマ数は `wave.sh` 冒頭の値で変える。出力は `out/wave_1920x540.mp4`(v2 の音入り)。

## 線 → メッシュの波形(その場で見るプレビュー)

`viz/index.html`。書き出さずにブラウザで再生しながら確認する(WebGL2、ライブラリなし)。

    cd PrivatePJ/x-music-collage && python3 -m http.server 8280
    → http://localhost:8280/video/viz/index.html

メッシュの仕組みは、ユーザー指定の講義資料(田所淳「openFrameworks 3Dグラフィクス、メッシュの操作」の ofMesh の例)と同じ。
資料では格子の頂点を `z = sin(i*0.1+t)*10 + sin(j*0.15+t)*10`(横の波+奥行きの波)で動かし `drawVertices()` で点として描く。
ここでは sin を音の波形に置き換えた。

- 高さ(i, j) = X(i) + Y(j)。X = いまの 1/30 秒の波形(`wave.sh` の線と同じ)、Y = 同じ瞬間から始まる波形を奥行きの列に並べたもの
  (1列あたり `ytime` 点の平均。既定 6 点 × 401 列 = 横の 1.5 倍の時間幅で、資料の 0.1 : 0.15 に合わせた)。
- 頂点は 400×401 の正方形の格子(横は音 4 点おき)。点で描き、隠面処理はしない。視点はドラッグで回せる(ofEasyCam 相当)。
- 面は広がるにつれて縦軸まわりに回り、最後は 90 度向きが変わる(`turn`、回りきる広がりは `turnEnd`)。線のときは回っていない。
- 「広がり」0 では真横から見た中央の1列だけ = 線。広がるにつれ前後に列が増え、視点が上がり、Y の波が加わり、線は点に置き換わる。
  既定は 25.6 秒から開き始めて 153.6 秒(Break の頭)で全面(`GROW`)。
- 面は広がりきると端まで同じ明るさの正方形になる(真上から測って 482×482 px)。広がっている間だけ端をぼかす。
- 視点は面と同じ高さで水平(`tilt` 0)。面が広がりきったあと、真っ直ぐ面の内部へ進み、中心の手前で止まる
  (`DOLLY`、既定 153.6 → 204.8 秒で 0.8 まで。0.31 で手前の端を越えて内部に入る)。
- カメラが面の手前の端を越えて内部に入った時点(既定で約 175 秒)から、面は水平に回り続ける(`spin` 度/秒、既定 7 = 約 51 秒で 1 周)。
- 水平に見ると点が重なって白く飛ぶので、面になったときの点の明るさを下げている(`gain`)。
- 見た目の値はページ下のスライダー(既定値は `P`)。絵は時刻だけで決まるので、後で同じ絵をコマ単位で書き出せる。
- 確認用に `wm.drawAt(秒)`。ペインが裏にあると画面更新が止まるので、動きは Chrome などで開いて見る。
- `viz/rows.html` は前の案(奥の列 = 過去のコマの波形、線で描いて手前が奥を隠す)。

## 単独で動くアプリ版(Swift + Metal)

今後の絵の変更はこのアプリ版だけに入れる。Web 版(`viz/index.html`)は 2026-11-19 時点の絵のまま残してある。

Web 版との違い:
- 面は回らない。広がるときの 90 度の回転(`turn`、Web 版は 90)も、内部に入ってからの回転(`spin`、Web 版は 7 度/秒)も初期値 0。カメラが中心へ進んで止まるだけ。面の向きは、横の波が画面の横、奥行きの波が奥

`viz/index.html` と同じ絵を、ブラウザなしで出すアプリ。`app/` にソースがあり、外部ライブラリは使っていない。

```bash
app/build.sh                     # app/build/WaveMesh.app を作る(音源は x-music-collage_v9_master.wav を中にコピー)
app/build.sh ../../別の音源.wav   # 中に入れる音源を変える
open app/build/WaveMesh.app
```

- 音源はアプリの中(`Contents/Resources/audio.wav`)に入っているので、`WaveMesh.app` だけ持ち出しても動く。別の音源は「ファイル → 音源を開く…」か `--audio 音源` で読める
- 窓は1つ: 上が描画、下が操作(再生、位置、スライダー、色)。P で操作を隠すと描画だけになる
- 外部ディスプレイへの出力: 「出力先」で画面を選び「外部ディスプレイに出す」(O キー、⌘E)。その画面いっぱいに枠なしで同じ絵が出る(32:9 を保ち、上下は黒)。もう一度押すか Esc で止まる。外部の画面はマウスに反応しないので、操作は手元の窓で続ける。画面が抜かれたら出力は自動で閉じる。`--output` を付けて起動すると最初から出力する
- 外部ディスプレイが1枚もないときは、出力先に手元の画面だけが出る。そこへ出すと操作の窓が隠れるので Esc で戻る
- 操作: スペースで再生/停止、←→ で5秒(Shift で30秒)移動、ドラッグで視点、スクロールで寄る、ダブルクリックで視点を戻す、F で窓を全画面
- スライダーは Web 版と同じ項目(初期値の違いは上の「Web 版との違い」)
- 絵は 1920x540 で描いて、窓と出力先のそれぞれの大きさに合わせて写す(`--scale 2` で起動すると縦横2倍の 3840x1080 で描く)
- 絵は音の位置(出力の遅れを引いた値)から決めるので、Web 版と同じくコマ番号 = floor(秒×30) だけで決まる
- 確認用: `WaveMesh --scale 1 --shot 秒:出力.png`(画面を出さずにその時刻の絵を書き出す)、`--set 名前=値`(スライダーの値。視点は yaw / pitch / zoom)、`--mute --play --quit-after 秒`(動かして コマ数と音の位置を出力)
- Web 版との一致: v5 の音源で 8 つの時刻(10〜280秒)を 1920x540 で比べ、差は 255 段階で平均 0.3 以下、最大 18(点の縁の描き方の違い)
- シェーダーは起動時にソースから組むので、Xcode のプロジェクトも `metal` コマンドも要らない(`swiftc` だけ)

### 通し(モード 4)

波形メッシュで始まり、途中で脳のシーン(Curl noise の粒子)へ一瞬で切り替わる。キーは 4、起動時は `--set mode=3`。

- 切り替わるのは、`seqCut`(既定 83.2 秒)あたりの最初のクラップが鳴るコマ。v9 では 83.2 秒(1分23秒)で、ハイハット(`Hihat Code` とその相方)が 82.7 秒で抜けて、クラップだけのビートになる最初の一打。色の反転と同じコマ。
- 場面が替わるだけに見えないよう、通しでは波形のあいだも、脳のパートと同じ粒子(400 万個の光の粒)で描く。粒を毎コマ、波形メッシュと同じ式の面
  (高さ = 横の波 + 奥行きの波、広がり・カメラの前進も同じ)の上に並べ直している。粒の見え方が前後で同じになる。
- 切り替わったコマからは、並べるのをやめるだけ。粒は持たされていた速さ(ばらばらの向き、`seqBurst`)で弾け飛び、そのまま Curl noise の流れに乗って雲になる。
  カメラも切り替わりの瞬間は波形と同じ正面・同じ距離で、キックの切り替えとクラップの構図はそこから数え始める。手ブレ・マス目・赤い線は 1.5 秒かけて入り、
  粒の明るさは波形のあいだ 0.22 倍、切り替わりから 1.4 秒かけて上げる。波形のあいだは、スキャンも出さない。
- 切り替わりで待たせないよう、脳のシーンはこのモードにした時点で先に用意する。
- そのあとの進行は脳のシーンの値のまま: 90 秒から粒子が脳へ集まり始め(`bStart`)、19 秒かけて 109 秒で脳になる(`bLen`)。直後のキックで神経の網、109.6〜120.8 秒のハイハットでスキャン。

- 終盤の、クラップが終わってキックだけが続く区間(最後のクラップのあとの最初のキック 〜 最後のキックの 0.4 秒あと。v9 では 236.8〜297.1 秒)は、
  キックが鳴るコマごとに別の素材の別の場所へ切り替わる動画を流す。エフェクトは何も掛けない(ブルーム・色の反転・ゆらし・寄り・色ずれ・手ブレ、すべてなし)。
  - この区間の動画は、前もって 1 本に組んでおく: `python3 tools/kickreel.py ../x-music-collage_v9_master.cues.json 素材のフォルダ work/kickreel.mp4`
    (1920x540、30 コマ/秒、272 カット、60.3 秒)。`build.sh` がアプリの中に入れ、アプリはそれを頭から流すだけ(再生中に場所を選んだり頭出ししたりしない)。
    以前は再生中に素材を頭出ししていたが、細かい切り替えで間に合わず、同じ絵がくり返し出た。
  - 同じ所が二度出ないことは、場所の決め方で保証している: 素材ごとに、使う回数ぶんの場所を頭から終わりまで等間隔に割り振り(となりどうし 2.5 秒以上)、1 回に使うのは最長 0.4 秒。
    作るときに区間どうしの重なりを総当たりで確かめ、使った場所の一覧を `work/kickreel.csv` に書き出す。できた動画でも、別のカットどうしで同じ絵のコマが 0 であることを確かめた。
  - 曲や素材を変えたら `kickreel.py` で作り直す。動画がなければ、この区間も脳のシーンのまま。やめるには `seqVideo` を 0。

- 中ほどの、クラップがいちばん長く抜けてキック(とベース)だけになる区間(v9 では 147.1〜172.8 秒、771 コマ)は、タイポグラフィのパート(`app/Sources/Typo.swift`)。
  - 前半(147.1〜160.0 秒)は、Neuro Music Lab のサイト(https://neuromusic.sfc.keio.ac.jp/)のページアイコン(ヘッドホンをした横顔と波形)を白 1 色で中央に置く。文字は出さない。
    サイトのアイコン指定(`cropped-Square-Logo-*.png`)の元になっている大きい画像 `Square-Logo.png`(6785x7277)を取得して `assets/neuromusic_icon_source.png` に置き、
    `tools/logo_mask.py 元 出力 1600` で形を抜き出した(`assets/neuromusic_icon_mask.png`)。元の絵の色(波形の虹色、頭の灰色)は使わず、形だけを白で塗る。
    アイコンの右横には「NEUROMUSICLAB」の文字を白で置く(もらった画像 `assets/neuromusic_wordmark_source.png` から `logo_mask.py` で抜き出した `neuromusic_wordmark_mask.png`。幅は画面の 56%)。
    2 つをひとかたまりとして中央に置く。元の画像が小さい(幅 626 ピクセル)ので、ふちは拡大して決め直したもの。
    下の文字(Helvetica Neue Bold)は、アイコンの形が読めなかったときの代わりとして残してある。
  - (代わりの文字のとき)白い「Neuro Music Lab」を画面いっぱいに置いたまま動かさない。書体も文字の色も変えない。キックが鳴るコマで、背景の色だけが替わる(v9 では 103 回。間隔 0.1〜0.6 秒)。
  - 書体は Helvetica Neue Bold、字間 -0.02em。候補 23 書体を実際に組んで見比べて選んだ(`out/typo_font_candidates.png`)。選んだ理由は `Typo.swift` の先頭に書いてある:
    色の面と白い文字だけの画面なので、線の太さがそろい、文字の中の空きが大きく、小文字が大きくて 1 行が横にそろって見える、太めのグロテスク体がいちばん安定する。
  - 背景は、白い文字がはっきり読める濃い色 8 色(黒・赤・青・緑・マゼンタ・紫・オレンジ・青緑)。最初は黒で、続けて同じ色にはしない。色の一覧は `Typo.grounds`。
  - 区間の後半、シンセパッドが入る所(`logoFrom` 160.0 秒あたりの最初のキック。v9 の音を測ると、キックの合間に鳴り続ける音が 160 秒から入る)からは、
    文字のかわりに x-Music Laboratory のロゴを白で置く(`seqLogo`。0 で文字のまま)。背景の替わり方は同じで、黒から始めてキックごとに替わる(51 回)。
    ロゴの形は `tools/logo_mask.py` が `assets/xmusic_logo_source.png`(もらった画像)から抜き出した `assets/xmusic_logo_mask.png`。`build.sh` がアプリの中に入れる。
    元の画像が小さい(ロゴの幅 約 1070 ピクセル)ので、ふちは拡大して決め直したもの。きれいな元データ(SVG など)があれば差し替えたほうがいい。
  - 既定(`typoSim` = 1)では、背景は色の面ではなく、直前のドラマーのモデルのシミュレーション(青と赤の粒の地形、回るカメラ)をそのまま続けて映し、その上にロゴを白で重ねる。
ロゴと名前は、ブルームを掛け終わった絵の上に重ねるので、光らない。
    x-Music Laboratory のロゴのうしろ(160.0〜172.8 秒)は、小田急のドラムセッションの動画(`x-music-videos/notext/` の `Drum Session with Odakyu Railway …`。`build.sh` が `odakyu.mp4` として入れる)を、
    ロゴが出た時刻から頭出しして流す(`logoVideo`。0 にすると Neuro と同じモデルのシミュレーション)。動画にはエフェクトを掛けない。
    数式は 147.1 秒(`bEqTo`)で消える。うしろの明るさは `typoSimDim`(0.5 倍)。`typoSim` を 0 にすると、下に書いた「キックで色が替わる面」に戻る。
  - ブルームと色の反転は掛けない。
  - 区間は時刻の一覧から自動で決まる(クラップどうしがいちばん長くあく所。あいたあとの最初のキックのコマから、クラップが戻るコマの手前まで)。やめるには `seqTypo` を 0。

- ロゴのあと、クラップが戻る 172.8 秒から `fxTo`(198.4 秒)までは、小田急の動画をそのまま流し続けて、エフェクトをかける(`seqFx`。0 でやめる)。
  - キック・クラップ・金物(`Hihat Closed Modular Salient 2`、時刻の一覧の `metal`)のどれかが鳴るコマごとに、直前と違うエフェクトへ切り替える(v9 では 25.6 秒で 約 130 回)。
  - エフェクトは 16 種類で、どれも細い帯・細かいます目の単位でかかり、模様は 1 コマごとに入れ替わる:
    スリットスキャン(横・縦。細い帯ごとに前の時刻の絵。多めに出る)/ 帯のノイズ(反転・粗い階調・横ずれ)/ 色ずれ / ブロックのずれ / 横線のずれ / 鏡(何度も折り返す)/
    モザイク(帯ごとに細かさが違う)/ 白黒 2 階調 + 走査線 / 分割 / 縦ずれ / 色の入れ替え / 止め絵 / 横の筋 / 寄り / 残像。
    どのエフェクトにも、音が鳴った直後の 2〜3 コマだけ、細い横の帯が左右にずれる乱れを重ねる。波打つものと、輪が広がるものは使わない。
  - 音が鳴らないあいだも止まらないよう、16 分音符(0.1 秒 = 3 コマ)ごとにも切り替える(`fxGrid`。0 にすると鳴ったときだけ)。2 秒で 20 回ほど替わる。
    スリットスキャンなど前の時刻の絵を使うものは、直前 48 コマ(1.6 秒)ぶんの絵の履歴(960x270)から読む。
  - キックのブルーム(`fxBloom` 0.15 倍)とクラップの色の反転も掛かる。
  - 金物が入る所(v9 では 196.0 秒。そのあたりの最初のキック 196.2 秒)からは、小田急の動画をやめて、キックごとに素材を順番に 1 本ずつ回す動画に替える(`seqCycle`)。
    素材 20 本を名前の順に回し、ひと回りするごとに各素材の先の場所へ進む(131 カット、6 周半)。エフェクト・ブルーム・反転はそのまま掛かる。`fxTo`(236.8 秒)まで続き、終盤のキックだけのパートへつながる。
    この動画も前もって 1 本に組む: `python3 tools/kickreel.py ../x-music-collage_v9_master.cues.json 素材のフォルダ work/cyclereel.mp4 196.008`(最後の値が、順番の版を始める秒)。
    `build.sh` がアプリの中に入れる。使った場所の一覧は `work/cyclereel.csv`。
  - 172.8〜297.1 秒はずっと動画になったので、粒子がもう一度脳に集まるのは、終盤の動画が終わる 297.1 秒から(`bReformFrom`)。
  - 操作欄の時刻の横と `--shot` の `note=` に、いまのエフェクトの名前が出る。`--shot` で確かめるときは `--warm 2` で履歴をためる。

- 終盤のキックのパート(236.8〜297.1 秒)では、画面の中央に細い文字(Helvetica Neue UltraLight)で日付を重ねる(`seqDate`)。パートの頭が 2016/09/01、終わりが 2026/11/22 で、
  その間(3734 日)を一定の速さで数える(1 コマに約 2 日)。数字が変わっても位置が動かないよう、1 字ずつ同じ幅のますに置く。日付は `Typo.swift` の `DateStamp.from` / `to`。
  パートが終わると、黒地に「2026/11/22」だけになる。その `dateGlowAfter`(5 秒)あとから `dateGlowLen`(4 秒)かけて、日付が消えていき、かわりに画面の中央に、
  ぼやけた淡い光(`dateGlow` = 明るさ、既定 0.26)が浮かぶ。光は中心から画面の下へ長く伸びる。曲の終わりまでその光だけ。

### 動画への書き出し

`./export.sh [出力.mov]`(既定は `out/xmusic_10th_1920x540.mov`)。通しの映像を、音つきの 1 本の動画にする。

- アプリの `--set mode=3 --export-raw コマ数` が、頭から 1 コマずつ順に描いた生の画素(1920x540、RGBA)を標準出力に流し、ffmpeg がそれを受けて動画にする。
  画面の取り込みではないので、コマ落ちも、取り込みによる劣化もない。粒子の動きは再生と同じく前のコマの続きとして計算する。
- 映像は ProRes 4444 XQ(色を間引かない 4:4:4)。数学的に完全な可逆ではないが、ProRes でいちばん上の画質で、粒子の細かい点もつぶれない。音は元の WAV のまま(PCM 24bit 48kHz)。
- 曲(6 分)のあとも最後の光を出し続ける。光が浮かび始める 302.1 秒から 10 分 = 902.1 秒で終わる。曲のあとは同じ絵なので、最後のコマを延ばしている(音は無音)。
- かかる時間は 3 分ほど(M5 Max)。進み具合は `out/export_log.txt`。
- 再生は `player/`(Playback.app)で。

### 脳のシーン(モード 3「Curl → 脳」)

3次元の空間を Curl noise の流れで漂う粒子が、脳の 3D モデルの表面に集まっていくシーン。キーは 3、起動時は `--set mode=2`。ソースは `app/Sources/Brain.swift`。

- **粒子**: 400 万個(`--particles 個数` で変えられる)。位置と速度を GPU(コンピュートシェーダー)で毎コマ 2 歩ずつ進める。
- **流れ**: ノイズを 4 段(だんだん細かく、向きを変えて)重ね、その「回転(curl)」を速度にする。傾きは差分ではなく式で直接求めている。
  curl だけだと粒子は一様な霧のままなので、ノイズの面へ寄せる力も足して、膜や筋にまとめている(`bSheet`)。
  一様にまいた直後は模様がないので、最初の 1 回だけ 24 秒ぶん先に漂わせてから始める。
- **脳へ**: 粒子ごとに、脳の表面の行き先(三角形の面積に比例してまいた点)と、その場所の面の向きを持つ。
  「脳になる量」(`bMorph`。負 = 自動で `bStart` 秒から `bLen` 秒かけて 0 → 1。既定 90 秒から 19 秒間)が上がると、
  粒子はうしろから前へ・場所ごとにずれて順に引かれ、流れに押されながら渦を巻いて着く。着いたあとも表面に沿った流れを少し残す。
- **描き方**: 粒子を光の点として足し込む(明るさの上限なしの絵に描き、あとで 0..1 に収める)。着いた粒子は、手前の面に隠れるものを描かず、
  面の向きで陰影をつける(しわが見える)。隠す側は行き先の位置に、粒子の半分だけを四角で描く(全部を丸で描くと 1 コマ 24 ミリ秒かかった)。
- **脳は粒の集まりとして描く**(既定): 着いた粒子のうち `bDots`(既定 0.10 = 1 割)だけを描き、うしろの粒も隠さない(`bSolid` 0)。面のある立体ではなく、透けて見える粒の雲になる。
  明るさ `bBrain` は 0.21(はじめに作ったときの 0.60 の 0.35 倍)で、神経の網が出ても変えない(`bNeuroDim` 1)。面として見せたいときは `bSolid` 1、`bDots` 1、`bBrain` 0.6。
- **音**: キックで流れが強まり(`bKick`)、脳の粒子が外へ跳ねる(`bPush`)。いまの波形で表面が細かく波打つ(`bWave`)。
  キックのブルームとクラップの反転も掛かる。粒子が密でそのままだと脳が白く飛ぶので、このシーンだけブルームを弱めている(`bBloom`、既定 0.3 倍)。
- **そのほかの値**: `bCurl`(流れの速さ)、`bFreq`(渦の細かさ)、`bEvolve`(流れが変わる速さ)、`bPull`(引き寄せる強さ)、`bSpin`(脳が回る速さ)、
  `bYaw`(向き)、`bScale`(大きさ)、`bSize`(粒子の大きさ)、`bCloud` / `bBrain`(明るさ)、`bExposure`(全体の明るさ)。視点はドラッグとスクロール。
- **マス目の面と原点の線**: 原点を中心に、xy・yz・zx の 3 枚の正方形の面をマス目(1 辺 20 ます)で描く。1 辺は粒子が漂う範囲のいちばん長い辺(7)の 1.5 倍
  (`bGridSize`、明るさは `bGrid`。0 で出さない)。脳のうしろに回った線は隠れる。原点には x・y・z 軸に沿ったごく短い赤い線を 3 本(`bAxis` = 片側の長さ、既定 0.12。`bAxisBright` = 濃さ)。
  赤い線は光として足さず、仕上がった絵の上に重ねる(足すと白い脳の上で見えなくなる)。通しの前半(波形のあいだ)は出さない。線の太さは `bLineW`(既定 2 px)。
  正面から見ると、yz と zx の面は真横から見ることになり、縦と横の 1 本の白い線に重なって見える(ドラッグで視点を回すと面として見える)。
- **カメラ**(時刻の一覧 `.cues.json` がある音源だけ。時刻だけで決まるので、位置を飛ばしても同じ絵になる):
  - キックで、原点のまわりを次の場所へすばやく大きく回り込む。1 回の角度は `bCamKick`(既定 1080 度 = 3 回転)の 0.6〜1.4 倍、たいてい同じ向きで、ときどき逆。高さも少し変わる。
    動きは、ばねとダンパー(車のサスペンションと同じ式)でつながれた点の動き: 行き先へ `bCamDur`(0.40 秒)で届き、そのまま通りすぎて、揺れ戻りながら収まる。
    通りすぎる量と揺れの長さは `bCamDamp`(0.50。小さいほど大きく長く揺れる。既定だと 16% ほど行きすぎる)。
    揺れが収まる前に次のキックが来たら、そのときの位置と速さから続ける(動きが途切れない)。
    前の回り込みから `bCamGap`(0.30 秒)たたないキックでは動かない(v9 では 882 個のキックのうち 547 回)。
  - 既定(`bCamCut` = 1)では、キックの回り込みは動きをつけず、鳴ったコマの頭で、原点のまわりの次の場所(`bCamKick` 既定 100 度の 0.6〜1.4 倍先)へぱっと切り替わる。
    上のばねの動きは `bCamCut` を 0 にしたときに使う(そのときは `bCamKick` を大きくすると何回転もする)。
  - クラップで、構図が「標準 / 寄り / 俯瞰」のどれかへ、鳴ったコマの頭でぱっと切り替わる(色の反転と同じコマ。動きはつけない)。毎回かならず違う構図になり、
    最後のクラップのあとは標準に戻る。寄りの距離は `bCamZoom`(0.5)、俯瞰の角度は `bCamTop`(62 度)。切り替えをやめるには `bCamClap` を 0。
  - 手ブレ: いつも掛かる、手持ちカメラのような揺れ(`bShake`。0 でなし)。ゆっくりした揺れをいくつか重ねたもので、カメラの位置は動かさず、
    向ける先(左右・上下)と傾きを揺らす。音量が上がると少し大きくなる。曲の時刻で決まるので、止めている間は揺れない。
  - 引きから寄りへ: 粒が漂っている間は `bCamWide`(既定 2 倍)の距離まで引いて流れの全体を見せ、脳ができあがる(脳になる量が 1 になる)につれて近づく。
    引いていく動きはつけない。脳のパートは最初のコマから引いた画角で始まる(通しでは、切り替わりのコマで一気に引いた画角になる)。クラップの「寄り」「俯瞰」は、この距離に掛け算で効く。
  - 光はカメラについて回る(どこから見ても左上の手前から当たる)。操作欄の時刻の横と、`--shot` の出力の `note=` に、いまの構図と向きが出る。
- **スキャン**: 1分あたりから入るオープンハイハットのような音(BASS の `Hihat Code`、v9 では 58.4〜76 秒と 103〜120.8 秒に 1.6 秒おき・計 24 回。時刻の一覧の `hat`)が鳴るたびに、
  水平なマス目の面が脳の上から下へ `bScanDur` で降り、面が通っている高さの粒子が帯になって光る。
  `bScanDur` の既定 0.36 秒は `Hihat Code` のサンプルの長さ(34575 点 / 96kHz。ノートは 0.1 秒だが、ワンショットで最後まで鳴る)。
  面と同じ高さには、その高さにあたる CT 画像(`brain-ct/slices/axial/` の頭の輪切り 41 枚のうち、脳のてっぺん〜底にあたる 4〜31 枚目。前後 2 枚を混ぜて送る)を、
  脳と一緒に回る水平な四角に貼って重ねる(`bScanCT` = 濃さ。黒い所は透ける。脳に隠さず上に描く)。大きさは、画像の中の頭の輪郭(幅 約 293 画素・前後 約 386 画素)が、脳のモデルの輪郭(幅 128mm・前後 178mm)にそろうように測って決めた
  (画像全体 154×210mm。頭の中心が画像の中心からずれているぶんも合わせてある)。輪郭どうしをそろえているので、画像の中の脳はモデルよりひと回り小さい。CT は `build.sh` が 3 方向ともアプリの中(`ct/axial` など)に入れる。出典は `brain-ct/SOURCE.md`(脳のモデルとは別の人)。
  帯の強さ `bScan`、幅 `bScanWidth`、面の明るさ `bScanLine`、面の大きさ `bScanSize`。
- **神経細胞の網**: 脳が完成した(`bStart` + `bLen`、既定 80 秒)あとの最初のキック(v9 では 80.0 秒)から、脳の中に線の網が伸び、`bNeuroDur`(1.6 秒)で脳じゅうに張り巡らされる。
  細胞 1800 個は、脳の表面の点を面の内側へ 3〜21mm 沈めた所に置き、近いものどうしを 3 本ずつ、ゆるく曲げた線でつなぐ(本物の神経の走り方ではなく、絵としての網)。
  5 か所の出発点からつながりをたどる順に伸び、先端は強く光る。伸びきったあとは信号が線の上を走り、キックで強まる。脳と一緒に回る。
  中の網が見えるよう、網が出ている間は脳の表面を暗くする(`bNeuroDim`、既定 0.35 倍)。網の明るさ `bNeuro`(0 で出さない)、太さ `bNeuroW`。
  「脳になる量」を手で決めているときは、1 にすると網が出て、それ未満では出ない。
- **クラップの写真**: `photoFrom`〜`photoTo` 秒(既定 102.0〜109.6。v9 では、キックだけの 96〜102 秒のあとにクラップが戻る 102.4 秒から、ハイハットが入る 109.6 秒の手前まで、38 回)の
  クラップでは、色の反転のかわりに、画面全体を CT 画像(`brain-ct/slices` の横断・冠状断・矢状断)で埋める。その間、3D の絵(粒子・マス目・赤い線)は出さない。
  出すのはクラップの瞬間だけ: 鳴ったコマの頭から最長 `bPhotoDur` 0.10 秒(3 コマ)、次のクラップまでの半分より長くはしない。それ以外(キックのときなど)は 3D の絵のまま。
  - 出し方は 5 種類で、続けて同じにはしない。方向・画像・ますの数は回ごとに変わる:
    その方向の断面を全部、順番に並べて画面を埋める / 画面いっぱいの 1 枚で、断面を順番に高速で再生する(鳴っている長さで脳の上から下まで通る) /
    3〜16 ますに割って、ますごとに少しずつずらして高速で再生する / 同じ 1 枚をとても小さくして一面に敷き詰める / 小さいますに断面を順番に敷き詰めて、再生もする。
  - ますの形に合わせて画像を切り出して埋めるので、画像と画像のあいだに黒い枠はできない(頭のまわりの黒は画像そのものの一部として残る。1 枚で出すときは、それが入らないところまで寄せる)。
  - やめるには `bPhoto` を 0(色の反転に戻る)。操作欄の時刻の横と `--shot` の `note=` に「写真 何番目 / 出し方 / 連番 / 何枚目」が出る。
- **ハイハットの間**(スキャンと同じ 0.36 秒、通しでは 109.6〜120.8 秒の 8 回): カメラが、脳を離れて眺める決まった位置へぱっと移る(`bHatCam`。向き `bHatCamYaw` 35 度、高さ `bHatCamPitch` 22 度、距離 `bHatCamZoom` 1.2 倍。毎回同じ場所)。鳴り終わると元のカメラに戻る。画面の両脇には、左に横断(スキャンの面と同じ番号)、右に矢状断の連番を、スキャンと同じ進み方で順に送る(`bScanSide`)。
- **キックとクラップの区間**(`bDissolveFrom`〜`bDissolveTo`、既定 121.6〜134.4 秒。脳がほどけていく区間と同じ): 粒子に色をつける(水色。`Brain.swift` の `TINT`、量は `bTint`)。
  クラップが鳴った瞬間、画面の真ん中の細い帯を残して、その上下の画素を端までまっすぐ引き伸ばす(`bStretch`)。帯はすぐ上下へ広がり、`bStretchDur`(0.22 秒)で元の絵に戻る。
  帯の最初の細さと位置は回ごとに変わる。仕上げの段(`post_fs`)でかけているので、ブルームも一緒に伸びる。
  左右への引き伸ばしは、この区間ではなく、ひとつ前のハイハットのスキャンの区間(`bStretchKickFrom`〜`bStretchKickTo`、109.6〜121.6 秒)のキックでかける(`bStretchKick`)。縦の帯を残して、その左右の画素を端まで引き伸ばす。こちらは `bStretchKickDur`(0.10 秒 = 3 コマ)で引く。
  マス目の線は、粒子に色がついている間も白のまま。白い粒子は `bWhite`(1.7 倍)で濃く(明るく)してある(色のついた区間とドラマーのモデルの区間は除く)。
  (脳を面で描く 3DCG らしい描画も作ったが、使わないことにした。`bSolidCG` を 1 にすると出る。)
- **脳がほどける**: `bDissolveFrom`〜`bDissolveTo`(既定 121.6〜134.4 秒。v9 では、ハイハットが終わってクラップとキックだけになる区間)で、できあがった脳が、集まったときと逆の順に
  Curl noise の雲へほどける(「脳になる量」が 1 → 0)。神経の網も一緒に消え、カメラは引いていく。`bReformFrom`(172.8 秒、タイポグラフィのパートの終わり)から `bReformLen`(8 秒)で、もう一度脳に集まる。
- **ドラマーのモデル**: `bModelFrom`〜`bModelTo`(既定 134.4〜147.2 秒。v9 では、金物のついたハイハット `Hihat Closed Modular Salient 2` が入る区間)は、粒子を
  藤井さんの論文(Fujii, Kudo, Ohtsuki, Oda, J Neurophysiol 2010)の式(6)で動かして、ポテンシャルの地形に並べる。`PrivatePJ/phase-landscape-metal` の地形と同じ式・同じ値
  (a = 1, b = 0, c = 2, ψ = 180°, d = 0.8Δω, √Q = 20°, 1 歩 0.01)を、このアプリのコンピュートシェーダーに書き直したもの。横 = 相対位相 φ、奥行き = Δω(0〜4)、高さ = V(φ)(式(A2))。
  谷(φ = 180° のあたり)に粒がたまり、Δω が大きい側では谷が消えて粒が坂を流れ落ち続ける。
  見た目も元の地形アプリに合わせてある: 落ち着いている粒は青、迷走した(360° を越えた)直後の粒は桃色がかった赤。地形の上に格子(φ は 45° ごと、Δω は 0.5 ごと)を引く。
  - 入り方: 134.4 秒から `bModelMove`(1 秒)かけて、粒子が Curl noise の雲の場所から地形の場所へ寄っていく。カメラも同じ時間で、直前の位置からモデル用の位置へ動く(切り替えにはしない)。
  - カメラは一定の速さで回るだけ(`bModelSpin` 9 度/秒、高さ `bModelPitch`、距離 `bModelZoom`)。キックの切り替え・クラップの構図・手ブレ・マス目・赤い線・スキャンは出さない。クラップでは色が反転する。
  - その上の画面の中央に、論文の式を 2 本だけ重ねる(`bEq` = 濃さ): 粒子を動かしている式 (6) と、地形の高さになっているポテンシャルの式 (A2)。式の番号は付けない。
    書体は数式用の STIX Two。変数は斜体、sin・cos・数字・かっこは立体、という数式の組み方にしている。
    式は `fujii-2010-paper/` の論文の本文から写した(`Brain.swift` の `makeEquationTexture`)。
- **脳のメッシュ**: `PrivatePJ/brain-mesh/` の左右の半球(`lh-nih3d.stl` / `rh-nih3d.stl`、55 万三角形)。`build.sh` がアプリの中に入れる。
  置き場所は `BRAIN_MESH_DIR` で変えられる。出典と利用条件は `brain-mesh/SOURCE.md`。
- **粒子の動きは積み重ね**なので、絵は時刻だけでは決まらない(位置を飛ばすと、そこから流れ直す)。`--shot` で確かめるときは `--warm 秒` で手前から進める。
  例: `--set mode=2 --set tTitle=0 --warm 31 --shot 64.238:出力.png`(自動の進行の途中)、`--set bMorph=1 --warm 6`(脳になりきった状態)。
- **速さ**(M5 Max、400 万個、3840x1080): 漂う状態で 1 コマ 約 8.5 ミリ秒、脳の状態で 約 11 ミリ秒(画面を出さずに測った値)。

### ハイハットで波形と背景の色が変わる

波形のあいだ(波形メッシュのモードと、通しの前半)、ハイハット(`Hihat Code`、時刻の一覧の `hat`)が鳴っている最中だけ、波形と背景に色がつく(`hatRed`。0 でしない)。
色の組は鳴るたびに次へ替わる(12 組: 赤×青、黄×紫、水色×赤、白×オレンジ、ピンク×緑、青×黄 …。`Audio.swift` の `Track.hatColors`。最初は赤×青)。
鳴っている長さはサンプルの長さ 0.36 秒(`bScanDur` と同じ値)。背景の色の濃さは `hatBlue`(0 で黒のまま)。v9 では 58.4 秒から 1.6 秒おきで、通しでは切り替わる 83.2 秒の手前まで 16 回。

### カメラの前進(波形メッシュ)

- 曲の頭からゆっくり進み始め、**一発目のキックが入る時刻**に決まった位置に着いて、そのあとは動かない(面の内部には入らない)。
- 着く位置は `Params.swift` の `DOLLY_END`(0.194)。以前の動き(153.6 → 204.8 秒で 0.8 まで進む)での 2分50秒の位置。
- 一発目のキックの時刻は、時刻の一覧(`.cues.json`)の最初のキック(v9 では 19.2 秒)。一覧がない音源では、音から測った値。
- 「カメラ前進」のスライダーを動かすと、手で決めた位置になる(負 = 自動)。
- 「広がり」(`GROW`、25.6 → 153.6 秒)は7分版のときのまま。

### キックでブルーム、クラップで反転(どちらのモードでも掛かる)

描いた絵に、最後に仕上げを掛ける。操作のスライダーは両方のモードに出る。

- **ブルーム**: 明るい所がにじんで光る。キックのたびに強く光って、すっと引く。`bloom`(キックで光る強さ。0 で切る)、`bloomBase`(いつも掛けておく強さ)、`bloomDecay`(引く速さ・秒)、`bloomThresh`(これより明るい所だけにじむ)、`bloomSize`(広がり)
- **反転**: クラップが鳴った1コマ(1/30秒)だけ、画面全体の色を反転する。`flash`(反転する量。0 で切る)、`flashVel`(これより弱いクラップでは反転しない)
- キックとクラップの時刻は、音からは測らず、Live セットのノートから作った一覧を読む(キックにスネアを重ねてあり、音だけではクラップと聞き分けられないため)。
  音源と同じ名前の `.cues.json`(`曲.wav` → `曲.cues.json`)があれば読む。`build.sh` はそれもアプリの中に入れる(`audio.cues.json`)
- 一覧を作る: `python3 tools/cues.py セット.als 出力.cues.json 0.008`(最後は、ノートの位置から音が立ち上がるまでの遅れ。v9 で測った値)。
  どの音を拾うかは `cues.py` の先頭の `LANES`。いまは キック = KIT の `kick_4`、クラップ = BASS の `Snare Slap RK`(セットに「クラップ」という名前の音はなく、これを当てた)
- v9 では キック 882 個、クラップ 430 個(32.6〜236.6 秒)。v9 の音の立ち上がりと突き合わせて、ずれは 0.01 秒ほど
- 一覧がない音源では、ブルームは音から測った低音の立ち上がりで光り、反転は出ない
- 反転は多い所で1秒に 7 回出る(1秒に 3 回を超える秒が 43 秒ぶんある)。強い点滅なので、人に見せる場では `flash` や `flashVel` で減らすことを考える
- 確認用: `--shot` の出力に `bloom=`(その絵のブルームの量)と `flash=`(反転の量)が出る。`--describe` で一覧の個数が出る

### タイトル(どちらのモードでも出る)

曲の頭で、黒地に文字がゆっくり浮かび上がって消える。

- 文字: 1行目「SHINYA FUJII」、2行目「10TH ANNIVERSARY SESSION」(1行目の半分の大きさ)。書体は Futura Medium の大文字、広い字間(候補6案からユーザーが選んだ方向)。文字は `Params.swift` の `titleLine1` / `titleLine2`
- 3 秒から 6 秒かけて浮かび上がり、20 秒から 6 秒かけて消える。時刻・大きさ・字間・明るさはスライダー
- タイトルが出ている間は、ほかの絵(動画、波形の線、点のメッシュ)を出さない。タイトルが消えるのに合わせて現れる(「タイトルの間は黒地に」を 0 にすると最初から出る)
- 確認用の絵: `out/title_preview.png`

### 動画モード(動画ファイルを音に合わせて出す)

**いまの初期値では、反応拡散(と、その中へ入る動き)、ライフゲームの重ね、波形で絵をずらす動きは、どれも出ない**(2026-11-19、いったん使わない方針。コードとスライダーは残してある: 「反応拡散」を負にすると自動、「ライフゲームの濃さ」「波形で横/縦にずらす」を上げると出る)。いま出るのは、タイトル → 動画(キックで切り替え、キックで寄る・明るくなる・色がずれる、手ブレ)。

窓の「モード」で「波形メッシュ」と「動画」を切り替える(1 / 2 キー)。動画モードは、選んだ動画ファイルを音に反応させて出す。

- 素材: 「動画を選ぶ…」でファイルかフォルダを選ぶ(複数可、mp4 / mov / m4v)。選んだものは次回の起動でも読み込む。起動時に `--video ファイルかフォルダ` でも指定できる
- 切り替え: 音の低音の立ち上がり(キック)で次の動画に切り替わる。「最短間隔」より短くは切り替えず、キックがなくても「最長間隔」たつと切り替わる。v5 の音と初期値(0.8 秒 / 12 秒)で 210 回(ドローンの部分は 12 秒ごと、ビートの部分はほぼ 1 秒ごと)
- どの動画のどこを出すかは切り替えの番号から決まる乱数で、毎回同じ。同じ動画は続けて選ばない
- 音への反応: その瞬間の波形で絵を横・縦にずらす(縦は波形の線と同じ形に曲がる)、キックで寄る・明るくなる・色がずれる。量はすべてスライダー
- ライフゲーム: 反応拡散が始まるまで(v6 で 76.8 秒まで)、細かい格子(横 480 ます = 1ます 4 ピクセル)のライフゲームを動画に重ねる。生きているますの中にだけ動画が見え、ますの外は真っ暗。反応拡散へ移る間に消えていく
  - 音から生まれる: そのコマの波形の線の上(音量が大きいほど多く)と、音の立ち上がり(ドローンの中の粒など)のたびに決まる1か所へまとめて
  - 音に合わせて進む: 世代の進む速さは音量で変わる(静かなときはゆっくり、大きいほど速く。目安は「ライフの進む速さ」世代/秒)
  - 止まった形がたまらないよう、ごく低い確率(1世代に 0.4%)で消える。端は反対側へつながる
  - 表示: 生きているますは小さな四角で、その中に動画が見える(色味を保って少し明るくする)。格子の位置にはごく薄い点。ますの外の明るさもスライダーで上げられる
  - この間は、波形で絵をずらさない(反応拡散へ移るのに合わせて戻る)。手ブレは残る
- 反応拡散: 最初のキックが入った時刻(v6 で 76.8 秒。音から自動で求める)から、動画に代わって、反応拡散(Gray-Scott)の模様が出る
  - 計算は画面と同じ形の格子(横 960)で、1コマあたり 14 歩。動画の明るさが場所ごとの性質を決める(暗いところ = 分かれて増える点、明るいところ = 珊瑚のように伸びる筋)ので、動画の絵に沿って模様の出方が変わる
  - 種は始まりの瞬間と、キックのたびに、動画の明るいところへ多くまく
  - 表示: 模様の中に動画の色(色味を保って明るくそろえる)、外は動画を暗くしたもの、ふちに陰影
  - 「反応拡散」を 0 以上にすると手で混ぜる量を決められる(負 = 自動)。開始の秒数、移る長さ(初期値 1.6 秒)、模様の動く速さ・細かさもスライダー
  - 最初のキックの求め方: 低音(250Hz より下)が直前に比べて大きく跳ねたコマのうち、強く、8秒以内にあと2回以上続く最初のもの(ドローンの中の単発の物音は拾わない)。この跳ね方は、動画の切り替えとキックへの反応にも使っている
  - 頭出しで離れた位置へ飛ぶと、模様は種からまき直して少し育てた状態で始まる(それまでの経過は再現しない)
- 中へ入る(入れ子のズーム): 反応拡散が始まって 12.8 秒後(v6 で 89.6 秒)から、カメラが画面の中心の模様へ寄っていく。その模様の中にまた反応拡散の世界があり、そこが画面いっぱいになると、またその中心の模様へ…と、終わりまで入り続ける
  - 仕組み: 計算は1つで、端のない正方形の領域(上下左右がつながっていて、どこまでも敷き詰められる。横 960 なら 960x960)。画面に出るのはその中央の 32:9 の帯。この同じ計算を 1/128 の大きさで、模様の中に「中の世界」として重ねる。深さが 1 進むと中の世界がちょうど元の大きさになり、それが新しい外側になる(くり返し)。階層ごとに左右・上下を裏返し、色味を少しずらす
  - 入口は、領域の中心にいつも置いてある点1つ。ほかの点と同じくらいの大きさ(半径 4〜5 ます)なので目立たない。128 倍に寄ると、この点が画面の角まで覆う(「入口の点の大きさ」で調整)
  - 中の世界は、入口の模様の形のまま、その中にだけ見える。はじめは模様の色の中に小さな模様が丸く浮かび、近づくにつれて中心から暗い地が広がる。中の世界は端がないので、枠や見切れは出ない(模様を出すのは中心まわりの領域1枚ぶんだけにして、同じ並びのくり返しが見えないようにしている)
  - 「入りながら回る」で、1階層入る間に絵を回すこともできる(初期値 0)
  - 速さ: 1階層に 6.4 秒(4小節)が基本で、キックが多い区間ほど速くなる(v6 で、終わりまでに約 54 階層)。キックのたびに少し前へ押し出される
  - 「中へ入る深さ」を 0 以上にすると、深さを手で決められる(負 = 自動)
- 手ブレ: 動画モードの絵全体が、手持ちカメラのように揺れる(ずれと傾き)。ゆっくりした揺れをいくつか重ねたもので、音量が上がると大きくなり、キックのたびに小さく突かれる。大きさは v6 で横・縦 ±9 ピクセル前後(1920x540 で)、傾き ±0.35 度ほど。「手ブレ」0 で止まる
- 動画は 32:9 いっぱいに敷き、はみ出す上下は切る(「動画の縦位置」で切り出す位置を動かす)
- 仕組み: 再生機を2台持ち、次の切り替えのぶんを先に頭出ししておいて、切り替えの瞬間に入れ替える。音とのずれが 0.15 秒を超えたら合わせ直す
- 確認用: `--warm 秒`(`--shot` の前に、その秒数だけ手前から1コマずつ進める。反応拡散が再生中と同じ状態になる)
- 確認用: `--set mode=1 --video フォルダ --shot 秒:出力.png`(その時刻の絵)、`--describe`(切り替えの数)、`--start 秒`(起動時の位置)。`--quit-after` の出力に、切り替えの回数と、切り替え後の絵が間に合わなかったコマ数が出る

動画の色をなめらかに補間してぼやけた色の面にする描画(色の格子、流れ、傾き)は、いったん入れたあと削除した(2026-11-19)。キックが入るまでは、動画を波形でゆらした絵がそのまま出る。
